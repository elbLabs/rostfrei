# Aggregate action

An aggregate action groups one state-changing capability beneath its aggregate. The trait is the stable contract, while `execute.rs` implements it directly for the matching `AggregateInstance`.

- Declare one `#[domain_action]` trait in `action.rs`.
- Implement it for `AggregateInstance<RentalFleetAggregate>`.
- Keep commands, events, handlers, and rejections in the same capability directory.
- Raise events inside the action implementation. The structure checker reports
  `RF011` for event raising outside validated action implementations in domain code.

Handlers call actions directly on loaded aggregates, with the action trait in scope:

```rust
let mut fleet = execution
    .load::<RentalFleetAggregate>(command.fleet_id.as_str())
    .await?;

match fleet.rent_bicycle(command.bicycle_id.clone()) {
    Ok(()) => Ok(CommandDecision::Accepted),
    Err(rejection) => Ok(CommandDecision::Rejected(rejection)),
}
```

The loaded handle forwards mutable access to its tracked aggregate instance;
the executor collects and commits the events raised by the action automatically.
Event-raising scope is enforced by `cargo rostfrei-dev check --workspace`, not by
Rust privacy. The check recognizes `.raise` and qualified `::raise` references,
including visible macro input, without resolving receiver types or expanding
macros. Mirrored domain tests are exempt.

Path: `src/domain/bike_rental/rental_fleet/rent_bicycle`

use rostfrei::domain_action;
