# Read models

A read model keeps a ready-made answer to a query. Domain-event and integration-event
handlers update it as facts arrive; queries read the saved value in one KV lookup.

You define the data, select the key each event affects, and describe the changes.
rostfrei handles loading, initialization, source checkpoints, compare-and-set
retries, and persistence.

```plaintext
BicycleAdded ───────────────┐
BicycleRented ──────────────┼──→ FleetActivity[city-fleet] ←── query
BicycleMaintenanceRequested ┘
```

The read model is application-owned query data. Aggregate history stays authoritative
in the EventStore, and external systems retain authority over their own facts.
An aggregate snapshot used to accelerate replay is a separate concept.

## Declare the data

Install [macro support](../domain-macros/install-macro-support.mdx) once at your crate root:

```rust
rostfrei::install_macro_support!();
```

Then declare an ordinary serializable struct:

```rust
#[derive(Default, serde::Serialize, serde::Deserialize, rostfrei::ReadModel)]
#[read_model(id = "fleet-activity", version = 1)]
pub struct FleetActivity {
    pub bicycles_added: u64,
    pub last_rented: Option<String>,
    pub last_maintenance_request: Option<String>,
}
```

The ID is a lowercase kebab-case name of 1–64 bytes. The schema version must be
positive. `Default` initializes a missing key. The runtime stores revisions and
source checkpoints outside your business fields.

Checkpoint metadata counts toward the value-size limit. Partition model keys when
joining an unbounded number of aggregate identities.

The derive declares metadata. [NATS setup](nats.mdx) explicitly binds
storage and starts the event consumers.

## Register event handlers

This view uses the bike-rental application's [fleet events](../../examples/bike-rental/src/domain/bike_rental/rental_fleet/event_set.rs)
and its public [maintenance request](../../examples/bike-rental/src/workshop.rs).
It is an optional projection; `bike-rental-api` does not start it. Each event
selects its fleet's row. The walkthrough's `city-fleet` is a valid `ReadModelKey`.
If you accept arbitrary `FleetId` strings, define a collision-free key mapping
within the 256-byte limit and use it for every handler and query.

```rust
let model = read_models
    .register::<FleetActivity>()
    .from_aggregate::<RentalFleetAggregate>()
    .try_on_domain_event::<BicycleAdded>(
        |event| event.fleet_id.as_str().to_owned(),
        |view, _event| {
            view.bicycles_added = view.bicycles_added.checked_add(1).ok_or_else(|| {
                rostfrei::ReadModelProcessingError::Transformation(
                    "bicycle count overflow".to_owned(),
                )
            })?;
            Ok(())
        },
    )
    .on_domain_event::<BicycleRented>(
        |event| event.fleet_id.as_str().to_owned(),
        |view, event| view.last_rented = Some(event.bicycle_id.as_str().to_owned()),
    )
    .on_integration_event::<BicycleMaintenanceRequested>(
        |event| event.fleet_id.as_str().to_owned(),
        |view, event| view.last_maintenance_request = Some(event.damage_report.clone()),
    )
    .build()
    .await?;
```

The first closure selects the read-model key. The second changes that key's value.
Use `on_domain_event` and `on_integration_event` for infallible transformations;
the `try_on_*` variants return `ReadModelProcessingError` when validation fails.

`from_aggregate` selects the owner of subsequent domain registrations. Switch it
to combine events from another aggregate in the same bounded context. If the payload
does not repeat the aggregate ID, the key selector can use committed metadata:

```rust
|event| event.recorded().stream_id().aggregate_id().as_str().to_owned()
```

Handlers are synchronous and repeatable. Keep external calls outside the transformation:
the runtime can invoke it again after a concurrency conflict or during a rebuild.

## Decode historical domain events

Domain events use the generated JSON codec by default. For custom or historical
formats, install the same frozen `AggregateCodecs` registry used by
`ApplicationBindings::with_event_codecs`:

```rust
let read_models = ReadModels::new(context, backend).with_event_codecs(codecs.clone());
```

Live delivery and history catch-up then decode through that registry. Registering
a source aggregate without a codec in it is a configuration error; it never falls
back to generated JSON. See [event schema evolution](../event-schema-evolution.md)
for registration and compatibility tests.

## Declare the integration producer once

A maintenance request needs no business-version field. Its `IntegrationEvent`
implementation names the context that publishes it:

```rust
impl rostfrei::IntegrationEvent for BicycleMaintenanceRequested {
    const EVENT_NAME: &'static str = "bicycle-maintenance-requested";
    const SCHEMA_VERSION: u32 = 1;
    const BOUNDED_CONTEXT: Option<&'static str> = Some("bike-rental");
}
```

The declared producer is checked by the typed publisher and read-model registration.
Without `BOUNDED_CONTEXT`, subscriptions default to the model's context. For an
existing unannotated contract, `integration_context::<E>(producer_context)` overrides
routing while retaining broker ordering.

**Broker ordering is the default.** The optional business-version policies are
explained in [ordering and recovery](ordering.mdx).

## Query the saved view

```rust
let reader = model.reader();
let key = rostfrei::ReadModelKey::new("city-fleet")?;
let activity = reader.read(&key).await?;
```

`ReadModelReader<FleetActivity>` is cloneable and returns
`Option<FleetActivity>`. Pass it into an
[application query handler](../runtime.md#application-queries-and-http). It exposes
no write methods or KV revision tokens.

`bicycles_added` counts add events over the fleet's history. `last_maintenance_request`
is the last request applied in broker order; redriving an older request can replace it.
Queries can observe a model that is still catching up. Freshness and authorization
deadlines belong in the application's contract.

## What the framework checks

- Domain inputs must be `DomainEvent` types in the selected aggregate's event set.
- Integration inputs must implement `IntegrationEvent`.
- Commands and queries cannot be registered as event inputs through these APIs.
- Registration rejects duplicate bindings, duplicate model IDs in one registry,
  incompatible bounded contexts, and cross-Normal/Test sources.
- Value and source progress are saved together. A failed transformation does not
  persist its partial in-memory changes.

## Run the complete example

To run the adapter's standalone example with Docker, start from the repository root:

```sh
cargo xtask test -- cargo run --locked -p rostfrei-nats --example read_model
```

The [example](https://github.com/elbLabs/rostfrei/tree/main/crates/rostfrei-nats/examples/read_model)

```plaintext
Some(FleetStatus { bicycles_registered: 1, rentals_open: true, inspection_passed: true })
```
