# Getting started

Use your coding agent to run the bike-rental example locally and inspect a successful rental and a rejection through Tracer.

## Explore with your agent

Copy this prompt into an agent that can read files and run commands in your local checkout:

```text
Help me explore Rostfrei through its bike-rental example. Use https://github.com/elbLabs/rostfrei and read docs/agent-tutorial.md from the checkout before setup. Check my environment, prepare an isolated local demo, and guide me through a successful rental and a rejection using real Tracer evidence. Explain one step at a time and let me choose what to inspect next. Use text by default; use a richer display only when its adapter is explicitly available.
```

The [agent tutorial guide](agent-tutorial.md) follows the current checkout. Let the agent check it before installing tools; a published skills kit may predate this guide.

## Prerequisites and connection

- Git and [Rust through rustup](https://rustup.rs/). The checkout pins its toolchain.
- Docker with Compose for the supplied local NATS broker, or a dedicated compatible NATS instance. The agent checks the setup and chooses isolated resources before running tests.
- A local agent with terminal access. The tutorial uses text and retained test evidence by default.

The [bike-rental README](../examples/bike-rental/README.md#run-locally) documents startup and Tracer settings. Tracer listens at `http://127.0.0.1:1309` by default; use the address and control token from your actual demo.

[Tracer Studio](../studio/README.md#tracer-connection) is an optional visual client. Only that path needs Node.js and pnpm; the text-first tutorial does not require frontend tooling.

## One framework dependency

Add `rostfrei` to your application's `Cargo.toml`. For a NATS application with
Tracer and development test helpers:

```toml
[dependencies]
rostfrei = { version = "0.1.3", features = ["nats", "tracer"] }

[dev-dependencies]
rostfrei = { version = "0.1.3", features = ["testing"] }
```

Domain macros, typed buses, execution, read models, and in-memory adapters are
available at the crate root. Enable only the adapters you need:

| Feature | Import path | Provides |
| --- | --- | --- |
| `nats` | `rostfrei::nats` | JetStream messaging, event stores, and KV read models |
| `http` | `rostfrei::http` | HTTP command and query routes |
| `tracer` | `rostfrei::tracer` | Diagnostics, observation, behavioral tests, Tracer HTTP, and fixtures |
| `fixtures` | `rostfrei::fixtures` | Versioned aggregate fixtures |
| `testing` | `rostfrei::testing` | Test harnesses and fixtures |

No adapters are enabled by default. Combine `nats` and `tracer` for the managed
application host; neither feature enables the other. Tracer's HTTP API lives at
`rostfrei::tracer::http`, separate from the application's `http` routes.

```rust
use rostfrei::{CommandBus, CommandHandler};
use rostfrei::nats::{NatsConnectionConfig, connect};
use rostfrei::tracer::{ApplicationBindings, NatsApplication};

rostfrei::install_macro_support!();
```

When upgrading from separate adapter dependencies, enable the corresponding
feature and replace imports such as `rostfrei_nats` with `rostfrei::nats`.
Lower-level contracts are available through `rostfrei::core`, `rostfrei::messaging`,
and `rostfrei::registry`. Existing root imports and direct adapter crates remain
supported; the facade re-exports the same types.

Declare other libraries your code uses, such as Serde, Tokio, and Axum, separately.
Install the [development CLI and Agent Skills](agent-skills-install.md) separately
too. The [generated starter](development.md#starter-dependency-contract) documents
its own release pin; the bike-rental checkout inherits dependencies with
`workspace = true`.
