# Domain service

A domain service owns stateless behavior involving domain objects supplied by its caller. `DomainServiceDefinition` connects the service to its bounded context.

- Put the service declaration and context definition together in `service.rs`.
- Put each action or policy in a child directory.
- Use an action to coordinate changes to domain objects.
- Use a policy to evaluate supplied facts without mutation.
- Keep repositories, messaging, persistence, and transaction execution outside the domain service.

`BicycleTransfer` validates and changes two fleets. Its application handler loads both fleets and the runtime commits their events atomically. The service's `transfer/execute.rs` implements `BicycleTransferAction` directly for `BicycleTransfer`.

Path: `src/domain/bike_rental/bicycle_transfer`

<ProjectStructureExample name="domain-service">

```rust
use rostfrei::{DomainService, DomainServiceDefinition};

use crate::domain::BikeRental;

#[derive(DomainService)]
#[domain(id = "bicycle-transfer", label = "Bicycle transfer")]
pub struct BicycleTransfer;

impl DomainServiceDefinition for BicycleTransfer {
    type Context = BikeRental;
}
```
